# V-MACS repository guidance

Keep this workspace as simple as possible. The user will supply materials, explain
the scope, share the PoC location and hardware, and discuss the design freely.

- Read the existing materials relevant to the discussion.
- Let the conversation guide the work; ask focused questions when needed.
- Preserve supplied materials and distinguish facts, assumptions, and proposals.
- Capture useful conclusions in concise repository notes as they emerge.
- Add structure only when actual content needs it. Avoid empty templates,
  formal registers, and mandatory IDs or decision workflows.
- Do not invent requirements, hardware specifications, or architecture choices.
- Check relative links and `git diff --check` after documentation edits.
